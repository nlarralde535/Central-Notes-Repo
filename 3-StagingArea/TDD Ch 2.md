The general TDD cycle
 - write a test ... invent the interface you wish you had
 - make it run: write the code necessary to pass the test, nothing more
 - make it right: remove any duplication or code smells introduced in the previous step

"The goal is clean code that works ... first we solve the 'that works' part ... then we solve the 'clean code' part. This is the opposite of Architecture-driven development where you first address the 'clean code' problem..."
